### 数据流核心原则

| 原则 | 说明 |
|------|------|
| **唯一数据源** | 表一 records[] 是所有计算的根本数据源 |
| **表二/表三** | `useMemo` 实时派生，不独立持久化（但支持自定义覆盖持久化） |
| **表四** | 通过 `updateCycleStats()` 手动生成，持久化到 R2 |
| **自定义覆盖** | 表二/表三支持 `customAnalysis` / `customMonthly` 开关，开启后覆盖实时计算 |
| **版本控制** | R2 存储层使用乐观锁 version 字段防止并发冲突 |

## 2. 表一：交易记录（TradingRecord）

### 2.1 字段定义

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | `string` | ✅ | 唯一标识，UUID |
| `openDate` | `string` | ✅ | 开仓日期，格式 `YYYY-MM-DD` |
| `stockName` | `string` | ✅ | 股票名称 |
| `stockCode` | `string` | ✅ | 股票代码 |
| `tradingType` | `TradingType` | ✅ | 交易类型（枚举，见 2.2） |
| `isSystem` | `YesNo` | ✅ | 是否符合系统：`是` / `否` |
| `hasMistake` | `MistakeStatus` | ✅ | 是否有失误：`是` / `否` / `其他` |
| `profitPercent` | `number` | ✅ | 盈亏百分比，正值盈利，负值亏损 |
| `holdDays` | `number` | ✅ | 持仓天数 |
| `chart1` / `chart2` | `string?` | ❌ | 截图文件 key |
| `keyChart1` / `keyChart2` | `string?` | ❌ | 关键截图 key |
| `preMarket` | `YesNo` | ✅ | 是否盘前：`是` / `否` |
| `hasCycleStats` | `boolean` | — | 系统标记：该记录是否已纳入周期统计 |
| `hasMonthlyStats` | `boolean` | — | 系统标记：该记录是否已纳入月度统计 |
| `cycleId` | `string?` | — | 关联的周期 ID |

### 2.2 tradingType 枚举（当前）

```typescript
type TradingType =
  | '齐飞水底'
  | '齐飞水底三等量'
  | '齐飞前多踩MA'
  | '风险释放平台转一致'
  | '双阳平台转一致'
  | '非系统';
```

共 6 个枚举值，为固定硬编码。

### 2.3 分类维度说明

表一通过以下 3 个维度进行多级分类，所有后续统计均基于这些维度展开：

| 维度 | 字段 | 取值 | 用途 |
|------|------|------|------|
| 系统归属 | `isSystem` | `是` / `否` | 区分系统类/非系统类 |
| 失误标记 | `hasMistake` | `是` / `否` / `其他` | 系统类内部细分有无失误 |
| 交易类型 | `tradingType` | 6 个枚举值 | 按交易策略细分 |

## 3. 表二：总数据统计（AnalysisResult）

### 3.1 数据模型

```typescript
interface AnalysisResult {
  // 系统维度盈亏比 (isSystem='是')
  systemProfitRatio: number | 'N/A';           // 所有系统记录
  systemNoMistakeProfitRatio: number | 'N/A';   // 系统 + 无失误 (hasMistake='否')
  systemWithMistakeProfitRatio: number | 'N/A'; // 系统 + 有失误 (hasMistake='是')
  nonSystemProfitRatio: number | 'N/A';         // 非系统 (isSystem='否')

  // 平均持仓天数
  systemProfitAvgHoldDays: number | 'N/A';      // 系统盈利平均持仓
  systemLossAvgHoldDays: number | 'N/A';        // 系统亏损平均持仓
  nonSystemProfitAvgHoldDays: number | 'N/A';   // 非系统盈利平均持仓
  nonSystemLossAvgHoldDays: number | 'N/A';     // 非系统亏损平均持仓

  // 按交易类型盈亏比 (单类型)
  typeQifeiShuidi: number;               // 齐飞水底
  typeQifeiShuidiSandengliang: number;   // 齐飞水底三等量
  typeQifeiQianDuoCaiMA: number;         // 齐飞前多踩MA
  typeFengxianShifang: number;           // 风险释放平台转一致
  typeShuangyang: number;                // 双阳平台转一致
  typeFeiXitong: number;                 // 非系统 (按 tradingType)

  // 聚合盈亏比 (多类型合并)
  qifeiShuidiZong: number;  // 齐飞水底总 = 齐飞水底 + 齐飞水底三等量 + 齐飞前多踩MA
  zhuanYiZhi: number;       // 转一致 = 风险释放平台转一致 + 双阳平台转一致
}
```

### 3.2 生成方式

**文件位置**：`src/stores/recordsStore.ts` + `src/hooks/useAnalysis.ts` → `useAnalysisResult()`

```
决策链:
  customAnalysis.useCustom === true
    → 直接返回 customAnalysis.data（用户自定义值）
    → 否则实时计算：
      遍历 records[] 全量记录，对每个字段执行对应计算函数
```

**自定义覆盖机制**：编辑器（DataEditor）中表二标签页可切换 `useCustom` 开关，手动覆盖任意字段值。覆盖后 R2 持久化。

### 3.3 各字段计算规则详表

#### 3.3.1 盈亏比类字段（通用公式）

**计算函数**：`src/utils/calculations.ts` → `calculateProfitRatio()` / `calculateProfitRatioByType()` / `calculateProfitRatioByMultipleTypes()`

**统一盈亏比公式 v3**：

```
Step 1: 筛选符合条件的记录
Step 2: 分别累加 profitPercent > 0 的盈利和 profitPercent < 0 的亏损绝对值
Step 3: 判断边界条件
  - 盈利和 = 0 且 亏损和 = 0   →  返回 'N/A' 或 0（按交易类型为 0）
  - 仅盈利和 > 0 (全盈利)       →  返回 盈利和 / 1.00
  - 仅亏损和 > 0 (全亏损)       →  返回 -(亏损和 / 1.00)
  - 两者均 > 0                  →  larger / smaller，盈利多则为正，亏损多则为负
Step 4: 结果保留 2 位小数 (parseFloat(x.toFixed(2)))
```

| 字段 | 筛选条件 | 计算函数 |
|------|----------|----------|
| `systemProfitRatio` | `isSystem === '是'` | `calculateProfitRatio(records, '是')` |
| `systemNoMistakeProfitRatio` | `isSystem === '是' && hasMistake === '否'` | `calculateProfitRatio(records, '是', '否')` |
| `systemWithMistakeProfitRatio` | `isSystem === '是' && hasMistake === '是'` | `calculateProfitRatio(records, '是', '是')` |
| `nonSystemProfitRatio` | `isSystem === '否'` | `calculateProfitRatio(records, '否')` |
| `typeQifeiShuidi` | `tradingType === '齐飞水底'` | `calculateProfitRatioByType(records, '齐飞水底')` |
| `typeQifeiShuidiSandengliang` | `tradingType === '齐飞水底三等量'` | `calculateProfitRatioByType(...)` |
| `typeQifeiQianDuoCaiMA` | `tradingType === '齐飞前多踩MA'` | `calculateProfitRatioByType(...)` |
| `typeFengxianShifang` | `tradingType === '风险释放平台转一致'` | `calculateProfitRatioByType(...)` |
| `typeShuangyang` | `tradingType === '双阳平台转一致'` | `calculateProfitRatioByType(...)` |
| `typeFeiXitong` | `tradingType === '非系统'` | `calculateProfitRatioByType(...)` |
| `qifeiShuidiZong` | `tradingType IN ['齐飞水底','齐飞水底三等量','齐飞前多踩MA']` | `calculateProfitRatioByMultipleTypes(...)` |
| `zhuanYiZhi` | `tradingType IN ['风险释放平台转一致','双阳平台转一致']` | `calculateProfitRatioByMultipleTypes(...)` |

#### 3.3.2 平均持仓天数字段

**计算函数**：`src/utils/calculations.ts` → `calculateAverageHoldDays()`

**聚合方式：算术平均**

```
Step 1: 按 isSystem + profitType 筛选记录
Step 2: 收集所有符合条件的 holdDays
Step 3: avg = sum(holdDays) / count(holdDays)
Step 4: 四舍五入保留 2 位小数
如果无符合条件的记录 → 返回 'N/A'
```

| 字段 | 筛选条件 |
|------|----------|
| `systemProfitAvgHoldDays` | `isSystem='是'` + `profitPercent > 0` |
| `systemLossAvgHoldDays` | `isSystem='是'` + `profitPercent < 0` |
| `nonSystemProfitAvgHoldDays` | `isSystem='否'` + `profitPercent > 0` |
| `nonSystemLossAvgHoldDays` | `isSystem='否'` + `profitPercent < 0` |

## 4. 表三：月度盈亏比统计（MonthlyAnalysis）

### 4.1 数据模型

```typescript
interface MonthlyAnalysis {
  month: string;                          // YYYY-MM
  systemProfitRatio: number | 'N/A';
  systemNoMistakeProfitRatio: number | 'N/A';
  systemWithMistakeProfitRatio: number | 'N/A';
  nonSystemProfitRatio: number | 'N/A';
  avgProfitRatio: number | 'N/A';         // 月度所有记录的平均盈亏比
  totalProfit: number | 'N/A';            // 月度所有记录的盈亏总和
}
```

### 4.2 生成方式

**文件位置**：`src/stores/recordsStore.ts` + `src/hooks/useAnalysis.ts` → `useMonthlyAnalysis()`

```
决策链:
  customMonthly.useCustom === true
    → 直接返回 customMonthly.data
    → 否则实时计算：
      Step 1: 遍历 records[], 按 openDate 提取 YYYY-MM 分组
      Step 2: 按月份升序排列
      Step 3: 对每个月的记录集执行计算
```

### 4.3 各字段计算规则

| 字段 | 计算函数 | 聚合方式 |
|------|----------|----------|
| `systemProfitRatio` | `calculateProfitRatio(monthRecords, '是')` | 盈亏比公式 v3 |
| `systemNoMistakeProfitRatio` | `calculateProfitRatio(monthRecords, '是', '否')` | 盈亏比公式 v3 |
| `systemWithMistakeProfitRatio` | `calculateProfitRatio(monthRecords, '是', '是')` | 盈亏比公式 v3 |
| `nonSystemProfitRatio` | `calculateProfitRatio(monthRecords, '否')` | 盈亏比公式 v3 |
| `avgProfitRatio` | `calculateAvgProfitRatio(monthRecords)` | 盈亏比公式 v3（全量不筛选） |
| `totalProfit` | `calculateTotalProfit(monthRecords)` | `sum(profitPercent)`，四舍五入 2 位小数 |

### 4.4 聚合维度

- **分组键**：`openDate` 的 `YYYY-MM` 部分（通过 `extractMonth()` 提取）
- **聚合粒度**：每月一组，组内对当月所有 record 的全量或条件筛选子集进行计算

## 5. 表四：周期盈亏比统计（CycleStats）

### 5.1 数据模型

```typescript
// 11 类统计类型（CycleStatType）
type CycleStatType =
  | '系统' | '系统无失误' | '系统有失误' | '非系统'
  | '齐飞水底' | '齐飞前多踩MA' | '风险释放平台转一致'
  | '双阳平台转一致' | '齐飞水底三等量'
  | '齐飞水底总' | '转一致';

// 单个周期统计条目
interface CycleStats {
  cycleId: string;          // 周期唯一标识
  statType: CycleStatType;  // 统计类型
  startDate: string;        // 该周期首条记录日期
  endDate: string;          // 该周期末条记录日期
  recordCount: number;      // 该周期内记录数
  isComplete: boolean;      // 是否满 30 条（完整周期）
  profitSum: number;        // 盈利总和（保留 2 位小数）
  lossSum: number;          // 亏损绝对值总和（保留 2 位小数）
  profitRatio: number|null; // 盈亏比（带符号，保留 2 位小数）
  recordIds: string[];      // 参与统计的记录 ID 列表
  createdAt: number;
  updatedAt: number;
}

// 统计结果容器
interface CycleStatsResult {
  stats: Record<CycleStatType, CycleStats[]>;
  generatedAt: number;
}
```

### 5.2 生成方式

**文件位置**：`src/services/cycleStatsService.ts` → `generateCycleStats()`

**触发时机**：仅通过 DataEditor 的「生成周期盈亏比统计」按钮手动触发。

**生成算法（方案 C — 动态增量）**：

```
对每类 CycleStatType 独立处理：

Step 1: 从所有 records 中筛选 matchesStatType() 为 true 的记录
Step 2: 按 openDate 升序排列
Step 3: 检查是否存在不完整周期（现有 incomplete cycle）
  → 有：将不完整周期的 recordIds + 新增符合条件的 records 合并重排，重新切分
  → 无：直接对符合条件的 records 切分
Step 4: 每 CYCLE_SIZE=30 条切为一个周期
  → length === 30 → isComplete = true
  → length < 30    → isComplete = false（不完整周期，末尾余数）
Step 5: 对每个周期的 records 调用 calculateProfitRatio() 计算 profitSum / lossSum / profitRatio
Step 6: 完整周期的 record 标记 hasCycleStats=true，关联 cycleId
```

### 5.3 11 种统计类型 → 记录匹配规则

**核心函数**：`matchesStatType(record, statType)`

| statType | 匹配条件 |
|----------|----------|
| `系统` | `record.isSystem === '是'` |
| `系统无失误` | `record.isSystem === '是' && record.hasMistake === '否'` |
| `系统有失误` | `record.isSystem === '是' && record.hasMistake === '是'` |
| `非系统` | `record.isSystem === '否'` |
| `齐飞水底` | `record.tradingType === '齐飞水底'` |
| `齐飞水底三等量` | `record.tradingType === '齐飞水底三等量'` |
| `齐飞前多踩MA` | `record.tradingType === '齐飞前多踩MA'` |
| `风险释放平台转一致` | `record.tradingType === '风险释放平台转一致'` |
| `双阳平台转一致` | `record.tradingType === '双阳平台转一致'` |
| `齐飞水底总` | `tradingType IN ['齐飞水底','齐飞水底三等量','齐飞前多踩MA']` |
| `转一致` | `tradingType IN ['风险释放平台转一致','双阳平台转一致']` |

**关键设计**：每条 record 可同时出现在多个 statType 的周期中（交叉覆盖）。例如一条 `tradingType='齐飞水底'` 的记录同时被「系统」「齐飞水底」「齐飞水底总」三类周期统计纳入。

### 5.4 周期盈亏比计算公式

**函数**：`cycleStatsService.ts` → `calculateProfitRatio(records)`

```
Step 1: profitSum = sum(所有 profitPercent > 0 的值)，保留 2 位小数
Step 2: lossSum = sum(所有 profitPercent < 0 的 Math.abs(值))，保留 2 位小数
Step 3: 边界判断
  - profitSum=0 且 lossSum=0 → profitRatio=null
  - profitSum=0 → profitRatio = -lossSum
  - lossSum=0 → profitRatio = profitSum
  - 两者>0 → larger/smaller，profitSum>lossSum 为正反之负
Step 4: profitRatio 保留 2 位小数
```

## 8. R2 持久化架构

### 8.1 存储结构

```
R2 Bucket
└── trading-data/records.json
    {
      "records": TradingRecord[],             // 表一
      "version": number,                      // 乐观锁版本号 (Date.now())
      "customAnalysis": CustomAnalysisData,    // 表二自定义覆盖
      "customMonthly": CustomMonthlyData,      // 表三自定义覆盖
      "cycleStats": Record<CycleStatType, CycleStats[]>,  // 表四
      "cycleStatsGeneratedAt": number | null   // 表四生成时间戳
    }
```

### 8.2 保存时机

| 触发操作 | 保存方式 |
|----------|----------|
| `setRecords()` / `addRecord()` / `updateRecord()` / `deleteRecord()` | 防抖保存（1 秒 debounce）→ `saveToR2()` |
| `updateCustomAnalysisField()` / `toggleUseCustomAnalysis()` | 防抖保存 |
| `addCustomMonthly()` / `updateCustomMonthly()` / `deleteCustomMonthly()` | 防抖保存 |
| 手动「更新统计数据」按钮 | `updateCycleStats()` → 立即 `saveToR2()` |

### 8.3 乐观锁冲突处理

```
client 保存时发送 current version
server 端：
  - 对比 R2 中 version 是否 > client version
  - 冲突时返回 { conflict: true, records: 最新数据, version: 最新版本 }
  - 客户端接收冲突响应后，覆盖本地 state 为服务器最新数据
  - 用户需重新操作
```

### 8.4 API 端点

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/records` | GET | 加载全量数据 |
| `/api/records` | POST | 保存全量数据 (含 version 校验) |
| `/api/files` | GET/POST/DELETE | Excel 文件上传/下载/删除 |
| `/api/update-stats` | POST | Worker 端直接更新统计（备用） |

## 9. 手动更新统计流程

### 9.1 触发入口

DataEditor 底部：「生成周期盈亏比统计」按钮

### 9.2 执行流程

```
1. 用户点击按钮 → handleUpdateStats()
2. 调用 updateCycleStats() (store action)
   ├── 清除所有 records 的 hasCycleStats / cycleId 标记
   ├── 调用 generateCycleStats(cleanRecords, emptyStats)
   │   ├── 对 11 个 CycleStatType 分别：
   │   │   ├── 筛选 matchesStatType 符合条件的记录
   │   │   ├── 按 openDate 升序排列
   │   │   ├── 每 30 条切一个周期
   │   │   ├── 计算 profitSum / lossSum / profitRatio
   │   │   └── 标记完整周期记录的 hasCycleStats=true
   │   └── 返回 { result: CycleStatsResult, updatedRecords }
   └── set state: records, cycleStats, cycleStatsGeneratedAt, statsNeedUpdate=false
3. 调用 saveToR2() 持久化到 R2
4. 首页图表自动响应 state 变化重新渲染
```

### 10.5 聚合规则可配置化

**现状**：

```typescript
// 硬编码
'齐飞水底总' = ['齐飞水底', '齐飞水底三等量', '齐飞前多踩MA']
'转一致' = ['风险释放平台转一致', '双阳平台转一致']
```

**优化后设计方向**：

```typescript
interface AggregateRule {
  name: string;           // 聚合规则名称（如 '齐飞水底总'）
  includedTypes: string[]; // 包含的交易类型枚举值列表
}

interface AggregateConfig {
  rules: AggregateRule[];  // 可多条聚合规则
}
```

**存储位置**：`trading-data/aggregate-config.json`

**变更联动规则**：

| 变更操作 | 联动目标 |
|----------|----------|
| 新增聚合规则 | 表二新增对应字段、表四新增 CycleStatType、首页各图表新增对应线/柱 |
| 修改聚合规则成员 | 表二/表四的计算结果自动变化（因 `matchesStatType` 中 OR 条件的成员变化） |
| 删除聚合规则 | 表二移除字段、表四移除类型、首页图表移除对应项 |
