## 一、项目概览

### 1.1 系统定义

**做什么**: 股票交易记录的录入、统计分析、多维图表可视化、Excel 导入导出、周期统计、图片管理、多数据集隔离。

**不做什么**: 不连接券商 API、不提供多用户/权限管理、不支持移动端原生 App。

### 1.2 术语表

| 术语 | 英文 Key | 含义 |
|------|---------|------|
| 盈亏比 | profitRatio | 盈利之和 / 亏损绝对值之和（带符号），较大者做被除数 |
| 系统 | system | `isSystem='是'`，符合交易系统规则 |
| 非系统 | nonSystem | `isSystem='否'`，不符合系统 |
| 齐飞水底总 | qifeiShuidiZong | 齐飞水底 + 三等量 + 前多踩MA 三种类型聚合 |
| 转一致 | zhuanYiZhi | 风险释放平台转一致 + 双阳平台转一致 聚合 |
| 周期 | cycle | 每 30 条记录为一个周期，按 `openDate` 排序后截取 |
| 数据集 | dataset | 一组隔离的交易记录，可独立切换和管理 |
| 后续盈亏空间 | subsequentProfitSpace | 交易结束后到下一个交易日的盈亏百分比 |

### 2.3 状态管理架构

三个独立 Zustand Store，通过 `useStoreSync` hook 协调跨 Store 的 R2 读写：

```
recordsStore (Zustand)
├── state
│   ├── records: TradingRecord[]          ← 表1 唯一数据源
│   ├── cycleStats: Record<CycleStatType, CycleStats[]>  ← 表4
│   ├── customAnalysis: { useCustom, data }      ← 表2 自定义覆盖
│   ├── customMonthly: { useCustom, data }        ← 表3 自定义覆盖
│   ├── fieldConfig: FieldConfig                  ← 字段配置
│   └── statsNeedUpdate: boolean                  ← 统计过期标记
├── actions (CRUD + 自定义覆盖 + 统计)
│   ├── addRecord / updateRecord / deleteRecord / setRecords
│   ├── setCycleStats
│   ├── setCustomAnalysis / updateCustomAnalysisField / toggleUseCustomAnalysis
│   ├── setCustomMonthly / addCustomMonthly / updateCustomMonthly / deleteCustomMonthly
│   └── setFieldConfig

datasetStore (Zustand)
├── state
│   ├── datasets: Dataset[]               ← 数据集列表
│   └── currentDatasetId: string | null   ← 当前选中的数据集
├── actions
│   ├── createDataset / deleteDataset
│   └── setCurrentDatasetId / setDatasets

uiStore (Zustand)
├── state
│   ├── isLoading / isSaving
│   ├── isInitialized / error
│   └── currentFileName
└── actions
    └── setIsLoading / setIsSaving / setError / setIsInitialized / setCurrentFileName

useStoreSync (Hook, 胶水层)
├── initializeFromR2() → 从 R2 加载数据到各 Store
├── switchDataset(id) → 切换数据集（加载新数据）
├── saveNow() → 立即保存到 R2
├── saveFieldConfigToR2() → 独立保存字段配置
├── updateCycleStats() → 生成周期统计并保存
└── useEffect debounce → 监听 records/customAnalysis/customMonthly/cycleStats 防抖保存
```

## 三、数据模型

### 3.1 TradingRecord（表1）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string (UUID) | 主键 |
| openDate | string (yyyymmdd) | 开单时间 |
| stockName | string | 股票名称 |
| stockCode | string | 股票代码 |
| tradingType | TradingType | 交易类型（可配置枚举） |
| entryType | EntryType | 交易切入类型（可配置枚举） |
| isSystem | '是'\|'否' | 是否符合系统 |
| hasMistake | '是'\|'否'\|'其他' | 有无重大失误 |
| profitPercent | number | 盈亏% |
| holdDays | number | 持仓天数 |
| subsequentProfitSpace | number\|null | 后续盈亏空间（null=N/A） |
| preMarket | '是'\|'否' | 盘前是否 |
| images | string[] | 图片文件名列表 |
| imagePrefix | string | 图片文件名前缀（YYMMDD） |

### 3.2 Dataset

```typescript
interface Dataset {
  id: string;
  name: string;
  createdAt: number;
  updatedAt: number;
}
```

### 3.3 AnalysisResult（表2）

从表1全量聚合，8个固定维度 + 按交易类型/切入类型的动态维度。

### 3.4 MonthlyAnalysis（表3）

按 `openDate` YYYY-MM 分组，每月独立聚合。

### 3.5 CycleStats（表4）

11个 CycleStatType，每30条一个周期。

| 首屏加载 (LCP) | < 3s |
| 图表渲染 (1000条) | < 500ms |

## 五、架构决策记录 (ADR)

### ADR-001: Store 拆分为 3 个独立 Store

**决策**: 将单体 `dataStore.ts` 拆分为 `recordsStore` / `datasetStore` / `uiStore`  
**理由**: 单一职责原则，records 变更不触发 UI 状态订阅者重渲染；R2 读写逻辑抽离到 `useStoreSync` hook。

### ADR-002: 图片存储采用 Chrome File System Access API

**决策**: 不使用 R2 存储图片（大文件），改用 Chrome 本地目录 + IndexedDB 持久化目录句柄  
**理由**: 免费额度限制、OCR 场景不需要云端存储图片、用户自主管理文件。

### ADR-003: 图片预览使用 Portal 渲染到 body

**决策**: ImagePreviewModal 通过 `createPortal` 挂载到 `document.body`  
**理由**: 避免 RecordModal (Headless UI Dialog stacking context) 遮挡按钮点击。

### ADR-004: 页面级代码分割

**决策**: App.tsx 使用 `React.lazy` + `<Suspense>` 分割 6 个页面  
**理由**: 首屏仅加载 Dashboard（~25KB），编辑器/导入/配置按需加载。
