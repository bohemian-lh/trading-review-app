## 一、项目概览

### 1.1 系统定义

**做什么**: 股票交易记录的录入、统计分析、多维图表可视化、Excel 导入导出、周期统计。

**不做什么**:
- 不连接券商 API 实时拉取交易数据
- 不提供多用户/权限管理
- 不支持移动端原生 App
- 不执行实时行情计算

### 1.2 术语表

| 术语 | 英文 Key | 含义 |
|------|---------|------|
| 盈亏比 | profitRatio | 盈利之和 ÷ 亏损绝对值之和（带符号），较大者做被除数 |
| 系统 | system | `isSystem='是'`，该笔交易符合交易系统规则 |
| 非系统 | nonSystem | `isSystem='否'`，不符合系统，含临时决策 |
| 齐飞水底总 | qifeiShuidiZong | 齐飞水底 + 齐飞水底三等量 + 齐飞前多踩MA 三种类型的聚合 |
| 转一致 | zhuanYiZhi | 风险释放平台转一致 + 双阳平台转一致 的聚合 |
| 周期 | cycle | 每 30 条记录为一个周期，按 `openDate` 排序后截取 |
| 重大失误 | hasMistake | 是/否/其他，表示该笔交易是否存在需要反思的重大失误 |
| R2 | Cloudflare R2 | S3 兼容对象存储，用于持久化 JSON 数据 |

### 1.3 技术栈

| 层次 | 选型 | 版本 | 选型理由 |
|------|------|------|---------|
| 框架 | React | 18.x | 生态成熟，组件化适合数据面板 |
| 语言 | TypeScript | 5.x | 类型安全，减少运行时错误 |
| 构建 | Vite | 5.x | 开发体验快，HMR 即时 |
| CSS | TailwindCSS | 3.x | 原子化样式，无需独立 CSS 文件 |
| 图表 | Recharts | 2.x | React 原生，声明式 API |
| 状态管理 | zustand | 4.x | 轻量，无 boilerplate，支持 selector |
| Excel | SheetJS (xlsx) | 0.20.x | 读写 .xlsx，无服务端依赖 |
| 持久化 | Cloudflare R2 | — | S3 兼容，免费额度充足 |
| OCR | Cloudflare Workers AI | — | llava-1.5-7b-hf 模型 |
| 部署 | Cloudflare Pages / Vercel | — | 静态托管，自动 HTTPS |

## 三、数据模型

### 3.1 实体关系

```
TradingRecord (表1)
  ├── id: string (UUID, PK)
  ├── openDate: string (yyyymmdd, 如 "20260605")
  ├── stockName: string
  ├── stockCode: string (6位数字字符串)
  ├── tradingType: TradingType (6种枚举)
  ├── isSystem: YesNo ("是"|"否")
  ├── hasMistake: MistakeStatus ("是"|"否"|"其他")
  ├── profitPercent: number (如 15.42 表示 15.42%)
  ├── holdDays: number (整数, >=1)
  ├── hasCycleStats: boolean (默认 false)
  ├── hasMonthlyStats: boolean (默认 false)
  └── cycleId?: string

TradingRecordInput (创建/编辑表单)
  └── 同上, profitPercent 和 holdDays 可 null

AnalysisResult (表2, 从 TradingRecord[] 聚合)
  ├── systemProfitRatio: number | 'N/A'
  ├── systemNoMistakeProfitRatio: number | 'N/A'
  ├── systemWithMistakeProfitRatio: number | 'N/A'
  ├── nonSystemProfitRatio: number | 'N/A'
  ├── avgProfitRatio: number | 'N/A'
  ├── totalProfit: number
  ├── systemProfitAvgHoldDays / systemLossAvgHoldDays
  ├── nonSystemProfitAvgHoldDays / nonSystemLossAvgHoldDays
  ├── typeQifeiShuidi / typeQifeiShuidiSandengliang / typeQifeiQianDuoCaiMA
  ├── typeFengxianShifang / typeShuangyang / typeFeiXitong
  └── qifeiShuidiZong / zhuanYiZhi ← 聚合类型 (v2.0 新增)

MonthlyAnalysis (表3, 从 TradingRecord[] 按月分组, 每月独立 AnalysisResult)

CycleStats (表4)
  └── Record<CycleStatType, CycleRecord[]>
      └── CycleRecord { startDate, endDate, recordCount, isFullCycle,
                         totalProfit, totalLoss, profitRatio, createdAt, updatedAt }
```

### 3.2 字段约束与默认值

| 字段 | 约束 | 默认值 | 空值处理 |
|------|------|--------|---------|
| id | UUID v4 | crypto.randomUUID() | 不可空 |
| openDate | 8位数字 | getDefaultOpenDate() | 不可空, 校验 ^\d{8}$ |
| stockCode | 非空字符串 | "" | import 时可为空串 |
| tradingType | 6种枚举 | "齐飞水底" | 不可空 |
| isSystem | "是"\|"否" | "是" | 不可空 |
| hasMistake | "是"\|"否"\|"其他" | "否" | 不可空 |
| profitPercent | number | null (表单) / 必填 (存储) | null 拦截 → 报错 |
| holdDays | integer >= 1 | null (表单) / 必填 (存储) | null 拦截 → 报错 |
| hasCycleStats | boolean | false | 自动标记 |
| hasMonthlyStats | boolean | false | 自动标记 |

|--------|---------|------|

### 4.4 可访问性

- 所有 button 必须有 aria-label 或可见文本

## 五、架构决策记录 (ADR)

### ADR-001: 选择 zustand 而非 Redux

**背景**: 需要全局状态管理 records/analysis/cycleStats 三个核心数据。

**决策**: 使用 zustand。  
**理由**: 
- 零 boilerplate，不需要 action creator / reducer 样板代码
- 原生支持 selector 防止不必要重渲染
- bundle < 1KB
- 支持在 React 组件外调用 `useDataStore.getState()`

**替代方案**: Redux Toolkit (拒绝，太重)；Context API (拒绝，性能差)

---

### ADR-002: analysis 和 monthlyAnalysis 作为派生状态而非独立存储

**背景**: analysis 完全可以从 records 计算得出。

**决策**: 两者独立存储在 state 中，但仅通过 `updateAnalysis` / `updateMonthlyAnalysis` 从 records 重算后写入。  
**理由**:
- 表 2 允许用户手动修改单个字段 (`updateCustomAnalysisField`)
- 导出时直接从 state 读取，不需要每次重新计算
- records 变更后自动触发重算 (`addRecord` → `updateAnalysis`)

---

### ADR-003: 盈亏比采用"较大者÷较小者带符号"规则

**背景**: 需要统一的盈亏比公式来比较盈利能力和亏损程度。

**决策**:
- 盈利大于亏损: `profitSum / Math.abs(lossSum)` → 正数
- 亏损大于盈利: `Math.abs(lossSum) / profitSum` → 负数
- lossSum === 0: 返回 `'N/A'`

**理由**: 同一个公式衡量盈利和亏损的不对称性，数值 >1 表示盈利能力强，< -1 表示亏损严重。

---

### ADR-004: 删除 SystemMistakeChart 合并到 CycleSystemChart

**背景**: "系统盈亏比趋势（按是否失误）"与其他图表功能重叠。

**决策**: 删除独立组件，作为 CycleSystemChart 的两条线（系统无失误 / 系统有失误）。  
**理由**: 减少图表数量，用户在一个图表中可对比系统/非系统/无失误/有失误四条线。

---

### ADR-005: 聚合统计类型（齐飞水底总/转一致）作为独立 CycleStatType

**背景**: "齐飞水底总"涵盖 3 种交易类型，"转一致"涵盖 2 种。

**决策**: 作为独立 STAT_TYPE，从表 1 直接计算，不聚合表 4 已有数据。  
**理由**: 表 4 每周期数据不足 30 条时会被截断，聚合已截断的数据会导致偏差。必须回到原始表 1 做全量计算。
