## 一、部署

### 1.1 环境要求

| 依赖 | 版本 | 用途 |
|------|------|------|
| Node.js | 18+ | 构建 |
| npm | 9+ | 包管理 |
| Cloudflare 账号 | — | R2 + Workers AI + Pages 托管 |
| Wrangler CLI | 3.x | Cloudflare 资源管理 |

### 1.2 开发环境启动

```bash
git clone <repo-url>
cd trading-review-app
npm install

# 创建 .env.local (参考 .env.example)
cat > .env.local << 'EOF'
VITE_R2_BUCKET_URL=https://your-bucket.r2.cloudflarestorage.com
VITE_WORKER_URL=https://your-worker.workers.dev
EOF

npm run dev
# → http://localhost:5173
```

### 1.3 生产构建

```bash
npm run build
# → dist/
# 内部执行: tsc && vite build && cp -r functions dist/
```

### 1.4 部署到 Cloudflare Pages

```bash
# 方式一: Git 自动部署
# 在 Cloudflare Pages Dashboard 中连接 GitHub 仓库
# Build command: npm run build
# Build output: dist/

# 方式二: Wrangler CLI 手动部署
npx wrangler pages deploy dist/
```

### 1.5 Cloudflare Workers 部署

项目需要两个 Worker（代码在 `functions/` 目录）：

1. **API Worker** (`functions/api/`): 代理 R2 存储操作 + OCR + 文本解析
2. **部署**:
```bash
cd functions
npx wrangler deploy api/worker.js --name trading-api
```

## 二、环境变量

| 变量 | 必需 | 默认值 | 说明 |
|------|------|--------|------|
| `VITE_R2_BUCKET_URL` | 是 | — | R2 Bucket 基础 URL |

| 变量 | 说明 |
|------|------|
| `R2_BUCKET` | R2 Bucket 绑定名称 |
| `R2_ACCESS_KEY_ID` | R2 Access Key |
| `R2_SECRET_ACCESS_KEY` | R2 Secret Key |
| `API_TOKEN` | 客户端认证 Token |

## 三、CI/CD 流水线

### 当前推荐: GitHub Actions + Cloudflare Pages 自动部署

```yaml
# .github/workflows/deploy.yml
name: Deploy
on:
  push:
    branches: [main]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 18
      - run: npm ci
      - run: npm run build
      - uses: cloudflare/pages-action@v1
        with:
          apiToken: ${{ secrets.CF_API_TOKEN }}
          accountId: ${{ secrets.CF_ACCOUNT_ID }}
          projectName: trading-review-app
          directory: dist/
```

## 四、R2 存储结构

```
{bucket}/
├── data/
│   └── trading-data.json     # 完整应用数据 (records + analysis + monthlyAnalysis + cycleStats)
└── config/
    └── header-keywords.json  # OCR 表头关键词配置
```

### 备份策略

| 频率 | 方式 | 保留期 |
|------|------|--------|
| 每日 | R2 自动版本控制 (Object Versioning) | 30 天 |
| 每周 | 导出 Excel → 本地存储 | 手动 |

**恢复步骤**:
1. 从 R2 版本历史恢复 `trading-data.json`
2. 或使用最近导出的 Excel → 前端 `导入 Excel` 功能重新导入

## 五、监控与告警

### 5.1 关键指标

| 指标 | 监控方式 | 阈值 |
|------|---------|------|
| 页面加载时间 | Cloudflare Web Analytics | > 5s 告警 |
| Worker 错误率 | Cloudflare Workers Analytics | > 5% 告警 |
| R2 读取延迟 | Workers Analytics | > 2s 告警 |
| OCR 调用失败率 | Workers Analytics | > 10% 告警 |

### 5.2 日志

项目使用 `console.log` / `console.error`。生产环境通过 Cloudflare Pages Dashboard → Logs 查看。

**关键日志点**:
- `saveToR2`: 保存成功/失败
- `loadFromR2`: 加载成功/失败（含数据大小）
- OCR 调用: 识别成功/失败
- `generateCycleStats`: 周期生成完成时间

## 六、故障排查

### 6.1 页面加载失败 (白屏)

| 可能原因 | 排查步骤 |
|---------|---------|
| Cloudflare Pages 部署失败 | Dashboard → Deployments → 查看构建日志 |
| R2 数据不可读 | 浏览器 DevTools → Network → 查看 `/api/data/load` 响应 |
| JavaScript 运行时错误 | DevTools → Console → 查看错误堆栈 |

### 6.2 数据保存失败

| 可能原因 | 解决方案 |
|---------|---------|
| R2 Token 过期 | 重新生成 Token → 更新 Worker 环境变量 |
| Worker 超时 | Workers Dashboard → Settings → 增加 Timeout |
| 数据过大 | 检查 `trading-data.json` 大小，考虑分片存储 |

### 6.3 OCR 识别失败

| 可能原因 | 解决方案 |
|---------|---------|
| 图片格式不支持 | 转换为 JPEG/PNG |
| Workers AI 模型限流 | Workers Dashboard → AI → 查看配额 |
| 图片过大 | 压缩到 5MB 以内 |

### 6.4 周期统计数据错误

**常见现象**: 周期统计图表数值与表 2 不一致。

**根因**: 周期统计按每 30 条截断，不是全量聚合。

**解决**: 点击"手动更新统计数据"按钮 → 从表 1 重新生成周期。

## 七、风险预案

| 风险 | 概率 | 影响 | 预案 |
|------|------|------|------|
| R2 写入失败 | 低 | 数据丢失 | localStorage 临时备份 (`r2-backup-{timestamp}`) + 导出 Excel 兜底 |
| Workers AI 模型下线 | 低 | 图片导入不可用 | 文本导入作为降级方案 |
| Cloudflare Pages 宕机 | 极低 | 服务不可用 | 本地 `npm run dev` 临时使用 |
| 枚举值升级导致旧数据不兼容 | 中 | 部分数据解析失败 | Zod schema 向后兼容 + 导入时自动迁移 |
| 大量数据导致性能下降 | 中 | 页面卡顿 | 表 1 虚拟滚动 (未来优化) + 周期截断已到位 |

## 八、常见操作

### 8.1 数据迁移（枚举值升级后）

```bash
# 1. 导出当前所有数据为 Excel
# 2. 运行迁移脚本 (如有)
node scripts/migrate-v2.js

# 3. 清空 R2 数据
# 4. 重新导入迁移后的 Excel
```

### 8.2 清空所有数据重置

1. 前端: 点击"清空所有数据"按钮
2. 确认弹窗: 二次确认
3. R2: 数据被覆盖为空

### 8.3 手动备份到本地

1. 点击"导出 Excel"
2. 保存 `.xlsx` 文件到本地
